# 心率监测插件 V1.0 需求规格

[English](REQUIREMENTS.en.md) | 简体中文

**状态：设计基线；未经开发或硬件验收。**

## 架构
单个 AstrBot 原生插件内部维护唯一 BLE 采集管理器。WebUI、指令及 AI 工具只能读取缓存或 SQLite，不得独立连接手环。采集失败不能阻塞 AstrBot 启动或影响 NapCat。

## 设备和采集
- 首发设备：Xiaomi Smart Band 9；首发宿主：原生 Windows。
- 优先验证标准心率服务 0x180D 和特征 0x2A37；必须先通过实际通知测试。
- 启动自动连接、持续收集、断线退避重连；用户可手动暂停。
- 连接、订阅、通知中断和插件重载分别处理；退出必须释放资源。
- 本机接收时间不应被描述为手环精确测量时间。无数据、数据过期与连接失败分别呈现。
- 不凭空插值、补点或把缺失值记为 0 BPM。

## 存储与统计
- SQLite 存储采集会话、原始心率、设备事件及分钟/小时聚合。
- 原始数据默认保留 90 天；分钟摘要建议 365 天；小时摘要长期保留。
- 清理前确保聚合成功；为查询建立时间索引，后台批量事务写入。
- 报告样本数和覆盖情况；明确样本平均值的定义，避免暗示完整全天测量。
- 可按日期查询、导出 CSV；应限制查询范围与返回记录量。
- 数据库放在 AstrBot 持久化数据目录，不能放在插件源码目录；不得提交公开仓库。

## WebUI
- 四页：实时监测、历史分析、设备管理、插件设置。
- 实时显示 BPM、最新通知时间、连接状态、5/30/60 分钟曲线及缺测断点。
- 历史支持自定义日期范围、分钟/小时聚合及导出。
- 设备管理提供扫描、绑定、连接/断开、重连次数和错误诊断。
- 所有管理 API 均验证 WebUI 管理权限；浏览器关闭后持续采集。
- 在实际 AstrBot 版本上验证受支持的插件视图接口，不修改 Dashboard 核心。

## QQ 与 AI
- 仅显式配置的本人 QQ 用户 ID 可访问。未配置时默认拒绝。
- 私聊返回心率；群聊默认不公开数据，必要时安全转私聊。
- 规划指令：当前心率、状态、今日/区间统计、历史和曲线。
- AI 工具只读，并在工具端验证用户权限；禁止任意 SQL、删除和蓝牙控制。
- 数据过期或离线时不返回伪实时值；不进行医学诊断。

## 安全和可靠性验收
1. Smart Band 9 实测可连接并接收有效通知。
2. 24 小时稳定性运行不导致 AstrBot 崩溃。
3. 热重载后不存在重复 BLE 任务。
4. 断线后可重连；蓝牙异常不会影响其他插件。
5. 90 天清理可复现，统计不因清理意外丢失。
6. 未授权的 QQ、AI、WebUI 请求均不能获得心率数据。
7. 无真实心率数据、设备地址或凭据进入 Git 仓库或默认日志。
8. 发布前确定实际 AstrBot 版本、接口、依赖和插件市场要求。

**发布门槛：** 以上验收通过后才发布可安装版本，不提前声称支持所有 BLE 心率设备。
