# AstrBot Heart Monitor V1.0 需求与验收规格

简体中文 | [English](REQUIREMENTS.en.md)

**状态：正式规划基线；尚未完成软件开发或真实设备验收。本文件定义目标，不代表功能已实现。**

## 1. 确定范围与语言政策

- 设备：Xiaomi Smart Band 9，已由用户确认存在“心率广播”菜单。
- 运行模式：**A+B 固定双通道**。通道 A 为原生 Windows AstrBot 插件内的 BLE 实时心率采集；通道 B 为无 Root Android Companion 的历史健康数据同步。
- 官方 Mi Fitness 保持安装和正常使用，不 Root、不修改官方 APK。
- 服务端作为 AstrBot 原生插件运行，不需要另起 Windows 桌面客户端或第二个常驻 Web 服务；Companion 为独立 Android APK。
- **AstrBot WebUI 仅简体中文，不提供中英切换。** Bot 回复、插件配置提示默认简体中文，V1.0 不要求英文界面/指令反馈。
- **GitHub 文档必须中文、英文双语**：README、需求、后续安装/发布/贡献者文档成对维护；代码标识及通用协议术语无需强制翻译。Android Companion 英文 UI 不是 V1.0 必需。
- 原始心率记录保留 **90 天**；Bot 私人查询仅限明确绑定的本人，未绑定默认拒绝。
- 同主版本 AstrBot 的小版本更新按实际接口能力验证，不硬编码单一精确补丁版本；大版本升级加强兼容审查。

## 2. 架构与故障隔离

Smart Band 9 → (A) Windows BLE GATT → AstrBot Core；Smart Band 9 → Mi Fitness → Health Connect → Android Companion → 受保护上传接口 → AstrBot Core。共用 SQLite、权限、分析、WebUI 与 Bot 服务。

- 通道 A 和 B 独立运行、独立健康状态，任一失败不阻塞另一通道、AstrBot 或 NapCat。
- 一份 BLE 连接管理器，WebUI、Bot、AI 工具仅从缓存/数据库读取，不额外连接手环。
- 实时显示优先通道 A；通道 B 的历史心率不得替代实时值。
- Windows BLE 能力缺失时仅降级通道 A，Android 历史接收可继续运行；Companion 缺席不阻塞 A。
- 所有时间写入 UTC；保存来源、事件与有效性信息。

## 3. 通道 A：BLE 心率广播

- 采用 Bleak 或经审查的兼容库，优先验证心率服务 `0x180D`、测量特征 `0x2A37` 的 GATT Notification；心率广播菜单不代表订阅已通过验收。
- 功能：设备扫描与显式绑定、连接与订阅、标准 BPM 解析、持续采集、队列/事务入库、断流检测、自动重连、休眠恢复及安全停止。
- 状态：Disabled、Scanning、Connecting、Subscribing、Streaming、Stale、Reconnecting、Unavailable、Error。
- 仅新收到的有效设备通知生成原始心率；无数据不补造样本、不写 0 BPM；Windows 接收时间不冒充手环精确测量时间。
- 建议初值：15 秒没有新通知标记过期；2 秒初始重试、最大 60 秒指数退避和抖动；参数可调整且需实机校准。
- 性能目标（通知到达后）：本地入库 P95 ≤1 秒，WebUI 展示 P95 ≤2 秒，均需测试验证；不保证设备每秒测量。
- 必测：与 Mi Fitness 共存、广播持续性、断开/回连、Windows 休眠、AstrBot 热重载后无重复 BLE 任务。
- 开源复用优先：先审查代码、许可证和维护情况；优先复用标准库/协议实现，禁止未经授权复制；不得引入需另外启动的 Windows 心率程序。

## 4. 通道 B：Android 历史同步

- 单独交付 Android Companion APK；无 Root，使用用户授权的 Health Connect API，不访问 Mi Fitness 私有存储、不注入 Hook。
- 目标数据：Mi Fitness 实际共享的步数、睡眠时段与阶段、运动、距离、热量、运动心率。血氧、压力、全天心率等没有验证外部来源的指标仅保留扩展能力，不列为 V1.0 必达。
- 组件：权限管理、数据源适配器、按数据类型维护增量游标、同步调度、离线持久队列、配对凭据管理、网络客户端、状态与错误页面。
- 默认每 30 分钟请求一次周期同步，系统可能延迟；启动/手动同步、网络恢复补传、最近 48 小时校正。
- 离线队列默认配置目标为 7 天，不能静默丢弃未确认数据；队列满、权限撤销、Token 失效需明确报警及恢复策略。
- 读取 Health Connect 的额外历史/后台数据必须经过系统功能检查和对应授权；不假设所有设备和版本都支持。
- Android → AstrBot 使用主动 HTTPS 批量上传和服务端确认；不在公网暴露无保护接口。初版可通过可信局域网或受保护私有网络通信。

## 5. 接口契约与数据模型

- 版本化的数据传输协议（从 `1.0` 起），独立于 AstrBot 插件/Companion 版本。
- 配对注册、设备鉴权、批量记录上传、明确确认、同步状态查询、凭据撤销、协议兼容检查。
- 必要记录字段：record_id、device_id、source、metric_type、value/unit 或结构化区间、measured_at、可选 measured_until、received_at、quality、schema_version；来源更新时刻可选。
- 同来源按稳定 ID 幂等去重；跨来源不能仅依据时间戳或数值相等误删真实样本。
- 记录状态区分 Valid、Suspect、Invalid；实时查询另外标记 Stale、Missing；不把历史手机心率伪装成实时值。
- 睡眠/运动保留起止区间、阶段/类型及来源；统一 UTC，UI 展示可转换时区。

## 6. 存储与保留

- SQLite 位于 AstrBot 持久化插件数据目录，非源码仓库；需要索引、事务写入、适当 WAL、迁移和备份恢复。
- 数据实体：设备、原始心率、睡眠、运动、步数、可扩展指标、日汇总、同步任务/游标、设备事件、迁移历史。
- 原始心率 **90 天固定策略**；建议睡眠/步数/运动 365 天、其他健康原始指标 90 天、连接日志 30 天；汇总长期保存但支持删除。建议期限可在验收前进一步冻结。
- 每天小批次过期清理，避免阻塞采集；清理前确认必要统计已提交；报告样本数及覆盖率，不暗示缺失区间已测量。

## 7. WebUI：仅中文

- 六个界面：**总览、实时监测、历史分析、同步中心、设备管理、系统设置**。
- 所有面向用户的 WebUI 标题、菜单、提示、错误、按钮、图表说明均用简体中文；通用技术名、单位和协议标识可保留原文。
- **不开发语言切换菜单、自动语言检测或英文 WebUI 翻译资源**；不以英文 UI 作为测试项。
- 展示当前心率及新鲜度、BLE/Companion 独立状态、最近成功数据时间、趋势断点、历史区间、来源筛选、CSV/JSON 导出。
- 浏览器关闭不停止采集；实时事件流重连后不会触发第二个 BLE 采集器。
- 使用当前 AstrBot 实际支持的插件 Views/API，逐接口验证，不修改 Dashboard 核心。所有 API 需服务端权限检查。

## 8. Bot、隐私与安全

- 仅明确绑定的本人 QQ 平台 ID，在私人会话中查询；未绑定、非本人及群聊默认拒绝。
- 固定命令：心率、心率历史、健康、睡眠、步数、运动、周报、设备状态；AI 工具仅只读，且在数据访问层再次鉴权。
- 不提供任意 SQL、通过 AI 调用蓝牙控制或公开群聊健康结果。旧数据必须说明测量时间，不显示伪实时数值。
- Companion 一次性配对、独立设备凭据、撤销轮换、传输加密、请求大小限制；WebUI 管理和数据导出均经过授权。
- 默认日志不得包含个人心率明细、QQ ID、BLE 地址、凭据；数据仅供个人参考，不用于诊断或应急监护。

## 9. 阶段及验收门槛

| 阶段 | 交付物 | 必须验收 |
| --- | --- | --- |
| Phase 0 | 仓库和开源许可证审查、AstrBot API/设备验证计划 | 不擅自重写或复制来源不明代码 |
| Phase 1 | Windows BLE 采集适配器 | 真实 Smart Band 9 连续有效通知、断流及重连；验证 Mi Fitness 共存 |
| Phase 2 | 核心 SQLite 与生命周期 | 90 天清理可复现、重启/热重载不丢已落盘数据或复制任务 |
| Phase 3 | **中文** WebUI 与私人 Bot | 实时值、历史曲线、权限隔离、中文覆盖验收 |
| Phase 4 | Android Companion APK | 真实授权 Health Connect 数据、断网缓存与补传 |
| Phase 5 | A+B 集成 | 两通道独立、来源可追踪、幂等去重、统计无重复权重 |
| Phase 6 | 发布准备 | 72 小时实机运行、隐私安全、双语 GitHub 文档、兼容性和许可证审核 |

所有实机、自动化和模拟验证分别记录环境、步骤、预期/实际结果及证据；不得用模拟通过冒充真实设备通过。

**发布门槛**：未经验证的指标、设备兼容和 Android 数据访问不能标记为已支持；先阶段验收后正式发布。仓库保持“规划阶段”状态直到真实开发和验收取得证据。
